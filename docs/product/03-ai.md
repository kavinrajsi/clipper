# The AI Layer

**Phase 3.** Condensed spec — problem, approach, schema sketch, and the decisions that need making. This gets re-specified before it's built; the shape below is what the rest of the roadmap assumes.

This is the phase that decides whether Clipper is a business or a better-organised Upwork.

## Reuse triage

| Already built | Extend this | Genuinely new |
|---|---|---|
| `youtube_videos` — synced clips with view counts | Training/eval signal for what actually performed | — |
| `youtube_channel_stats_daily` | Performance baseline per creator | — |
| `campaign_submissions.video_url` | Input to quality scoring | — |
| `brand_profiles` — `font_name`, `color_code`, `description` | Seed of the brand voice profile | `brand_voice` |
| Supabase Storage (`avatars` bucket, client-side upload) | Pattern to copy; needs a new bucket and server-side signed uploads | `source_assets` bucket |
| `campaigns.description` / `requirements` | Target of brief auto-generation | — |
| — | — | **AI SDK, transcription, job queue, `pgvector`** |

**This is the first phase requiring real new infrastructure.** No AI SDK exists in `package.json` today — no `ai`, no `@ai-sdk/*`, no provider client. There's no job queue, no server-side media handling, and object storage is one public `avatars` bucket with client-side uploads. Budget this as a systems phase, not a UI phase.

## The inversion

Every competitor's flow starts with the buyer writing a brief:

```
Brand: has content, no time
  → must write a creative brief          ← the hard part, done by the wrong person
  → post job → review proposals → hire → wait → receive clips
```

Clipper's flow should start with the content:

```
Brand: uploads a 90-minute podcast
  → AI transcribes, detects 12 highlight candidates, scores each
  → brand watches 12 pre-cut previews, picks 3
  → campaign brief generates itself from the picked moments
  → fund → invite matched creators → creators work against
     concrete timestamps instead of prose
```

The brand never writes a brief. They make three yes/no decisions about their own content. That's a fundamentally easier job, and it's only possible if you're in the content pipeline rather than the contracting pipeline — which is exactly why an incumbent can't add it as a feature.

The second-order effect matters more than the first: **creators receive vastly better briefs.** "Cut the 14:32–16:05 exchange about pricing objections, hook on the 'nobody tells you this' line" produces a better clip, in less time, with fewer revisions, than "make it punchy." Everyone earns more per hour.

## Feature set

### Highlight detection

Transcribe the source asset, segment into candidate moments, score each for standalone comprehensibility, emotional arc, hook strength, and quotability. Return timestamped candidates with a rough cut preview.

The scoring signal that competitors can't replicate: **Clipper knows which past clips actually performed**, because `youtube_videos.view_count` is OAuth-verified and tied to the source moment through campaign lineage. That's a closed feedback loop from suggestion to measured outcome.

### Viral score

A 0–100 predicted-performance estimate on a clip or candidate, calibrated per-niche against delivered results. Shown to brands when picking candidates, and to creators before submitting.

**Be careful here.** A confidently wrong score is worse than no score. Ship it with visible confidence bounds and a calibration plot in `/admin`. If predicted-vs-actual correlation is weak, this becomes an internal ranking signal and never a user-facing number.

### Hook, caption, subtitle, hashtag generation

Straightforward LLM generation, differentiated by brand voice conditioning. Subtitles come free from the transcription already produced for highlight detection — same pass, different output. Burned-in subtitle styling should derive from the brand kit ([`04-workspace.md`](./04-workspace.md)), where `font_name` and `color_code` already exist.

### Thumbnail suggestions

Extract high-quality frames at emotional peaks, rank by face presence, expression intensity, and text-safe area. Frame extraction, not image generation — generated thumbnails misrepresent the content and get clips removed.

### Brand voice

A per-workspace profile learned from the brand's existing published content plus explicit guidance: tone, banned words, claims that need legal review, emoji policy, target audience. Conditions every generated caption, hook, and hashtag.

This is quietly the strongest retention mechanic in the product. A tuned brand voice is accumulated work that doesn't transfer to a competitor.

### AI quality score

Automated pre-submission check: audio levels, subtitle sync, aspect ratio, safe-area compliance, duration against platform limits, brief adherence. Runs before the brand ever sees the clip, so review cycles are spent on creative judgement rather than catching a wrong aspect ratio.

### Auto editing suggestions

Suggestions, not edits: tighten this pause, cut this filler, the hook doesn't land until 0:04 — move it to 0:00. Delivered as a timestamped checklist against the submission, using the annotation infrastructure from [`05-collaboration.md`](./05-collaboration.md).

Clipper does not build an in-browser editor. See the "deliberately not building" list in [`00-roadmap.md`](./00-roadmap.md).

## Schema sketch

```sql
-- Uploaded long-form content
create table public.source_assets (
  id uuid primary key default gen_random_uuid(),
  workspace_id uuid not null references public.workspaces(id) on delete cascade,
  uploaded_by uuid not null references auth.users(id),
  storage_path text not null,
  filename text,
  duration_seconds int,
  status text not null default 'uploaded'
    check (status in ('uploaded','transcribing','analysing','ready','failed')),
  transcript jsonb,
  created_at timestamptz not null default now()
);

-- AI-detected candidate moments
create table public.highlight_candidates (
  id uuid primary key default gen_random_uuid(),
  source_asset_id uuid not null references public.source_assets(id) on delete cascade,
  start_seconds numeric not null,
  end_seconds numeric not null,
  title text,
  rationale text,
  viral_score int check (viral_score between 0 and 100),
  score_confidence numeric,
  selected boolean not null default false,
  campaign_id uuid references public.campaigns(id) on delete set null,
  created_at timestamptz not null default now()
);

-- Every AI invocation: audit, cost, retry, credit accounting
create table public.ai_jobs (
  id uuid primary key default gen_random_uuid(),
  workspace_id uuid references public.workspaces(id) on delete cascade,
  user_id uuid not null references auth.users(id),
  kind text not null check (kind in (
    'transcribe','highlight_detect','viral_score','hook','caption',
    'subtitle','thumbnail','quality_score','edit_suggestions','hashtags'
  )),
  subject_type text,
  subject_id uuid,
  status text not null default 'queued'
    check (status in ('queued','running','succeeded','failed','cancelled')),
  input jsonb,
  output jsonb,
  model text,
  tokens_used int,
  credits_charged numeric,
  error text,
  created_at timestamptz not null default now(),
  completed_at timestamptz
);

-- Per-workspace generation conditioning
create table public.brand_voice (
  workspace_id uuid primary key references public.workspaces(id) on delete cascade,
  tone text,
  audience text,
  banned_terms text[] default '{}',
  required_disclosures text[] default '{}',
  emoji_policy text,
  sample_captions text[] default '{}',
  updated_at timestamptz not null default now()
);
```

`ai_jobs` is the spine. Every AI feature writes a row — which gives cost attribution, retry, debugging, credit metering ([`08-monetisation.md`](./08-monetisation.md)), and an eval dataset, all from one table. Build it first, before any individual AI feature.

Note `source_assets.workspace_id` — this assumes the Phase 2 workspaces migration has landed. That's the dependency ordering argument from the roadmap made concrete.

## Decisions to make before building

**1. Where does media processing run?** Transcription and frame extraction won't run in a Next.js route handler. Options: a provider API (fastest, per-minute cost), Vercel Sandbox or a container running ffmpeg (more control, more ops), or a dedicated worker. This choice determines the whole phase's architecture and should be settled before any schema lands.

**2. Which model provider, and behind a gateway?** Routing through a gateway rather than a single provider SDK keeps model choice reversible and gives per-feature cost observability. Worth doing from day one; retrofitting it after ten call sites exist is painful.

**3. Who pays for a failed job?** Credits must be charged on success, not on submission, with a documented policy for partial failures. Get this wrong and it's the top support complaint.

**4. Does the platform store source assets long-term?** Storage costs scale with content volume, not revenue. Propose: retain during an active campaign plus 30 days, then delete the media and keep the transcript and derived metadata (cheap, and it's what the feedback loop actually needs).

**5. Human review on generated claims.** Captions for regulated categories (health, finance, supplements) can generate claims that create real liability. `brand_voice.required_disclosures` is the hook; the policy needs writing.
